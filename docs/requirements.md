# rushVN 要件定義書

- 文書版: 0.6
- 作成日: 2026-09-26
- 状態: 閲覧専用の実装に着手。確定事項以外はレビュー用

## 1. 目的と決定状況

WinVN（VN）のようなUIを持つRust製NNTPニュースリーダーを開発する。
第一の利用目的は、ユーザーがfjのニュースグループを読むことである。
初版はニュースグループを選び、記事の流れを追い、本文を読む閲覧専用のデスクトップアプリとする。投稿機能は後続版で扱う。

| 項目 | 状態 | 内容 |
| --- | --- | --- |
| 製品の目的 | 確定 | WinVN（VN）のようなUIを備えるNNTPニュースリーダー |
| 実装言語 | 確定 | Rust |
| 主な閲覧対象 | 確定 | fjのニュースグループ |
| 接続先の初期値 | 確定 | サーバー名・ホスト名・認証情報は空欄。利用者が指定する |
| 作業場所 | 確定 | このリポジトリ用ディレクトリ |
| 製品名 | 仮称 | rushVN（ディレクトリ名に基づく） |
| 対応OS | 回答待ち | 提案: Windows・macOS・Linuxを想定し、最初の実機検証はmacOS |
| 初版の機能範囲 | 確定 | 閲覧専用。新規投稿・返信・下書きは後続版へ延期 |

上記の確定事項以外は提案であり、ユーザーの回答をもって確定する。本書の「必須」は、提案した初版スコープを採用した場合の必須要件を意味する。
実装済み・検証済みを表すものではない。

## 2. 利用者と主な利用シナリオ

対象は、まずfjの記事を読みたい利用者。日本語テキストの閲覧、返信関係の追跡、未読管理を優先する。ユーザーの指定により投稿機能は後続版へ延期する。初期のUI言語は日本語を提案する。

1. 接続先を登録し、接続テスト後にグループ一覧を取得する。
2. グループを検索して購読し、最新の記事一覧を取得する。
3. 未読記事を順に読み、返信関係をたどる。
4. アプリを再起動しても購読・既読状態が残り、取得済み本文をオフラインで読める。

利用するサーバーはユーザーが指定する。アプリ側で公開サーバーやアカウントを提供しない。
fjのグループ名と接続先NNTPサーバーは別の設定項目として扱う。接続先が希望するfj.*を配信し、閲覧を許可していることを実サーバー検証の前提条件とする。実サーバーでの認証後の一覧取得と本文取得は未検証。

### 2.1 fjを読む最初の到達点

接続先の初期値は空欄とし、利用者がサービスの案内に従って設定する。暗黙TLSの標準ポート563は入力補助として用意する。個人の接続設定・アカウント情報はリポジトリに含めない。

最初の実用上の到達点は、認証後にグループ一覧を取得し、`fj.*`に絞り、任意のグループを購読して日本語記事を読めること。この閲覧経路を初版で実装・検証する。

- `fj.*`による階層絞り込みを用意し、部分一致検索とは区別する。
- 未認証で見えるグループが制限される場合に備え、認証後にグループ一覧を再取得できる。
- 空のグループと取得失敗を区別する。掲載グループの存在だけで記事や新着があるとは判断しない。
- サーバーに保存されている記事を閲覧対象とし、過去のfj全履歴を取得できることは保証しない。


## 3. 初版の範囲（閲覧専用は確定、詳細機能は提案）

### 初版に含める

- 複数サーバーの登録・切り替え、TLS接続、ユーザー名とパスワードによる認証。
- グループ一覧、検索、購読、記事の差分取得。
- スレッド／一覧表示、本文表示、日本語文字コード対応。
- 未読／既読管理、取得済み記事の検索とオフライン閲覧。
- 接続失敗・記事失効からの回復操作。

### 初版の対象外

- 新規投稿、ニュースグループへの返信、投稿用画面、下書き保存（後続版へ延期）。
- バイナリ配布用途、NZB、yEnc、分割ファイル復元、添付ファイルの投稿・展開。
- SMTPメール送信、メール返信、メールボックス統合。
- HTMLのブラウザー相当表示、外部画像の自動取得。
- サーバー間の横断検索・記事統合、クラウド同期、自動投稿。
- cancel／supersedes等の制御記事、プラグイン、WinVN設定の完全互換。
- サーバー運用機能と記事配送機能。

対象外の記事でもアプリは停止せず、対応するテキスト部分または未対応の案内を表示する。
バイナリ対応やクラシックな複数ウィンドウが優先される場合は、このスコープを改訂する。

## 4. UI要件

### 4.1 画面構成案

3ペイン案はrushVN向けの提案であり、WinVNの画面をそのまま再現すると確定したものではない。

| 領域 | 表示・操作 |
| --- | --- |
| メニューバー・ツールバー | 接続、更新、検索、設定 |
| 左ペイン | サーバー、購読グループ、取得済み範囲の未読件数 |
| 右上ペイン | 記事の未読状態、件名、投稿者、日時、返信階層 |
| 右下ペイン | 件名、投稿者、投稿先、日時、本文、必要時の全ヘッダー |
| ステータスバー | 接続状態、取得進捗、オフライン状態 |

### 4.2 操作性

- ペイン幅・高さ、一覧列幅、文字サイズ、本文の折り返しを変更・保存できる。
- グループ移動、記事移動、次の未読、スレッド展開をキーボードだけで行える。
- ショートカットの具体的な割当はOSと画面方式の確定後に決める。入力欄の通常編集を妨げない。
- 未読・選択・エラーを色だけで区別せず、太字・記号・説明を併用する。
- 接続中も画面操作・キャンセルができる。再取得で選択記事やスクロール位置を不用意に失わない。
- 初回起動、未購読、空のグループ、本文未取得、接続失敗をそれぞれ区別して案内する。
- 日本語IME、コピー、文字選択、OSの表示倍率に対応する。
- メニュー・主要コントロールには支援技術から読めるラベルとフォーカス状態を持たせる。

## 5. 機能要件

| ID | 優先度 | 要件 | 受け入れ条件 |
| --- | --- | --- | --- |
| F-01 | 必須 | サーバー設定 | 名前・ホスト・ポート・接続方式・認証設定を登録、編集、削除できる。接続テストで成功／認証失敗／通信失敗を区別する |
| F-02 | 必須 | TLSと認証 | 暗黙TLSとSTARTTLS必須モードに対応。証明書を検証し、TLS失敗時に平文へ切り替えない。平文でパスワードを送らない |
| F-03 | 必須 | グループ取得・購読 | グループ名で絞り込み、購読・解除できる。購読設定が再起動後も残る |
| F-04 | 必須 | 記事概要の取得 | 初回は件数を制限し、古い記事の追加取得と新着差分取得ができる。中断後の再取得で行が重複しない |
| F-05 | 必須 | 記事一覧・スレッド | 一覧と返信ツリーを切り替え、件名・投稿者・日時で並べ替えできる。欠落した親や不正な参照循環で停止しない |
| F-06 | 必須 | 本文表示 | 選択記事の本文を取得し、引用と通常文を判別できる。全ヘッダーと元データを確認できる。失効記事は理由を表示する |
| F-07 | 必須 | 日本語記事 | UTF-8、ISO-2022-JP、Shift_JIS、EUC-JPのテキストとMIMEヘッダーを表示できる。文字コードを手動で変更できる |
| F-08 | 必須 | 既読管理 | 本文の表示成功で既読になる。手動で未読に戻せる。グループの既読化はその時点の既知の記事を対象とし、新着を巻き込まない |
| F-09 | 必須 | オフライン閲覧 | 保存済み概要・本文を接続なしで開ける。未取得本文は取得済みと区別される |
| F-10 | 必須 | ローカル検索 | 保存済みの件名・投稿者・本文を検索できる。本文未取得分を検索していないことが分かる |
| F-11 | 後続版 | 新規投稿 | 投稿先、差出人、件名、本文を編集し、確認後に送信できる。サーバー受理と全体への配信完了を混同しない |
| F-12 | 後続版 | 返信 | 元記事を引用し、Referencesを維持する。Followup-Toを尊重し、poster指定はメール返信未対応として案内する |
| F-13 | 後続版 | 下書き | 手動保存と自動保存を備え、再起動後に復元できる。投稿失敗や送信結果不明で内容を失わない |
| F-14 | 必須 | エラーとキャンセル | 通信中断、タイムアウト、認証失敗、記事失効を区別し、再試行できる。認証失敗を無限に再試行しない |
| F-15 | 必須 | 保存設定 | 購読、既読、画面配置、サーバー設定を保持。キャッシュ削除で購読・既読を消さない |
| F-16 | 次期候補 | フィルター | 投稿者・件名によるミュート、スレッド無視、重要記事マーク |
| F-17 | 次期候補 | 移行 | サーバーとの対応を指定した.newsrcの読み込み・書き出し |

### 5.1 記事と既読状態の意味

- サーバー・グループ・記事番号とMessage-IDを区別する。サーバーごとに記事番号空間を分離する。
- スレッドはReferencesとMessage-IDを基礎とする。件名が同じだけの記事を無条件に統合しない。
- 同一サーバー内のクロスポストはMessage-IDで関連付け、取得済みの同一記事へ既読を反映する。サーバー間の既読同期は初版では行わない。
- 未取得記事の既読状態や未読総数を断定しない。未読件数の対象範囲と取得済み範囲をUIで示す。
- 記事番号の欠番・失効・サーバーの番号範囲変化を扱い、最後の番号だけから未読件数を算出しない。

### 5.2 日本語とMIME

文字コード指定を優先し、指定なし・不正指定の場合はフォールバックと手動選択を用意する。
MIMEのBase64／quoted-printableをデコードし、multipartでは対応するtext/plainを表示する。
復号できない記事は元データを残して案内し、破棄しない。HTMLしかない記事は未対応表示と元データの確認を提供する。

### 5.3 後続版の検討メモ：投稿の状態と誤送信防止

本節とF-11〜F-13は初版の実装・受け入れ対象外。後続版で投稿文字コード、試験投稿先、下書きの保存・復元要件を改めて定める。実サーバーへの試験投稿には利用許可のあるテスト用グループを使う。

- 送信前に投稿先・差出人・件名・本文を確認する。複数グループへの投稿は宛先を明示する。
- 投稿可否を接続状態とサーバー応答から判定し、投稿禁止なら理由を表示する。
- 状態を「下書き」「送信中」「サーバー受理」「失敗」「結果不明」に分ける。
- 送信後の応答待ちで切断した場合は「結果不明」とし、自動再送しない。
- 送信対象の本文と識別情報を保持して照合に使う。記事がすぐ見つからないだけで未送信と断定しない。
- 再送はユーザー操作で行う。連打で並行送信しない。

## 6. 通信互換性と安全性

NNTPの基本は[RFC 3977](https://www.rfc-editor.org/info/rfc3977/)を参照し、初版のクライアントに必要な取得機能を対象にする。サーバー配送用の全機能の実装は要求しない。

- CAPABILITIES、グループ一覧、GROUP、OVER、ARTICLE等を必要に応じて使用する。
- 旧サーバー向けのXOVERおよびMODE READERは互換性検証の対象とする。未対応コマンドは明示的な応答に基づいて代替経路または対応外の案内へ移る。
- 複数行応答、CRLF、dot-stuffing、欠番、不正応答を扱う。

認証は[RFC 4643](https://www.rfc-editor.org/rfc/rfc4643.html)のAUTHINFO USER/PASSを初版対象とし、TLS上でのみ使用する。SASL専用サーバーは初版の対象外として明示する。
TLSは[RFC 4642](https://www.rfc-editor.org/info/rfc4642/)と更新文書[RFC 8143](https://www.rfc-editor.org/rfc/rfc8143.html)を参照する。接続方式は自動推測せず設定で指定し、暗黙TLSを初期推奨値とする。

- 証明書の期限・ホスト名・信頼チェーンを検証する。検証無効化を通常UIに設けない。
- 平文接続はローカル試験向けの明示設定に限定し、認証情報は送らない。
- パスワードの永続化にはOSの資格情報ストアを使用する。利用できない場合はセッション内保持とし、設定ファイルへ平文保存しない。
- ログにパスワード、認証ペイロード、記事本文を出力しない。
- 記事中のURLは明示操作で開き、自動的な外部リソース取得やプログラム実行をしない。
- 外部入力にはサイズ・時間・参照深度の上限を設け、超過を説明する。黙って本文を切り捨てない。

記事形式は[RFC 5536](https://www.rfc-editor.org/rfc/rfc5536.html)を参照する。詳細なヘッダー解析・MIME処理・コマンド遷移は基本設計で定める。

## 7. 非機能要件と検証目標（暫定）

以下の数値は実測値ではなく初期目標。試作時に検証マシン・ビルド方式・データセットを固定し、測定して見直す。

| ID | 項目 | 目標・確認方法 |
| --- | --- | --- |
| N-01 | 応答性 | 通信・保存処理でUIを停止させない。通常の選択・キー操作は100ms以内の反応を目標とする |
| N-02 | 一覧の規模 | 10万グループ、1グループ10万件の保存済み記事概要で検索・スクロールを実測する。表示行を必要に応じて描画する |
| N-03 | 起動・表示 | 上記データで保存済み画面の起動3秒以内、取得済み本文の表示200ms以内を目標とする |
| N-04 | 通信量 | 初回取得は最新1,000件を仮の初期値とし変更可能にする。本文は選択時取得を基本とする |
| N-05 | 保存容量 | 本文キャッシュ上限は仮に1GiB。古いキャッシュから整理し、購読・既読状態は保持する。概要と本文の使用量を区別して表示する |
| N-06 | データ耐久性 | 保存済みの購読・既読・設定が強制終了で破損しない。保存途中の中断後も整合した状態で再起動できる |
| N-07 | 互換性 | 採用OSごとにビルド、日本語IME、表示倍率、主要キーボード操作、資格情報保存を検証する |
| N-08 | 保守性 | NNTP処理、記事解析、保存、UIを分離し、外部サーバーなしで正常・異常系を再現できる |

対応OSの最低バージョン、配布形態、署名・公証、ライセンスはリリース設計で決定する。

## 8. 初版の受け入れシナリオ

| ID | 手順・条件 | 合格条件 |
| --- | --- | --- |
| A-01 | 空の設定からTLSサーバーへ接続し購読する | 接続・認証・グループ検索・購読が完了し、再起動後も設定が残る |
| A-02 | 日本語、欠番、欠落親、循環Referencesを含む固定記事を読む | 文字化けを修正でき、ツリー処理が終了し、本文を読める |
| A-03 | 記事を既読化し、クロスポスト先を開いて再起動する | 定義した範囲で既読が反映され、新着は未読として残る |
| A-04 | 取得済み本文と未取得本文をオフラインで開く | 保存済み本文は表示され、未取得は明示される |
| A-07 | 無効証明書、認証失敗、記事失効、取得中断を発生させる | 理由が区別され、資格情報が漏れず、UIから回復操作できる |
| A-08 | 購読・既読・設定を保存し、プロセスを強制終了して再起動する | 保存済み状態が復元し、キャッシュ削除でも失われない |
| A-09 | 大規模固定データでN-01〜N-03を測る | 測定条件と数値を記録し、未達なら原因と改訂案を示す |
| A-10 | 採用OSでキーボード操作・日本語IME・表示倍率を確認する | 主要シナリオが操作でき、入力や表示が欠けない |
| A-11 | 利用可能なアカウントで候補サーバーに接続し、fj.*を絞り込む | 購読と保存記事の本文取得ができる。記事がない場合は空の状態を確認し、日本語本文の検証は未実施として別記する |

モックサーバーの合格と実サーバーの互換性は別に記録する。実サーバー名・方式・検証日・検証機能を残し、未実施を合格扱いにしない。
初版では投稿用UIを設けず、POSTコマンドを送信しない。モックサーバーの通信記録で確認する。

### 8.1 後続版へ移した受け入れシナリオ

初版の完了条件には含めない。既存のIDは追跡のため維持する。下書きの保存・復元試験も後続版で追加する。

| ID | 手順・条件 | 合格条件 |
| --- | --- | --- |
| A-05 | 試験グループに日本語記事を新規投稿し返信する | サーバー受理を確認し、取得した記事の本文・投稿先・返信関係が一致する |
| A-06 | 投稿本文送信後、受理応答の直前で通信を切る | 結果不明と表示し、自動再送せず送信内容が残る |

## 9. 実装までの進め方

1. 要件の合意: 閲覧専用の方針に基づき、OS、詳細機能、UIの継承方針を決める。
2. UI試作: 固定記事で画面密度、キーボード操作、日本語IME、支援技術対応を確認し、GUI技術を選ぶ。
3. 閲覧の縦断実装: 接続→購読→記事一覧→本文→既読保存→オフライン閲覧を通す。
4. 初版検証: 異常系、大量記事、採用OS、許可された実サーバーで受け入れ確認を行う。

投稿・返信・下書きの設計と実装は、閲覧専用の初版の後に行う。

最初の実装ではegui/eframe、専用ワーカースレッド、SQLiteを仮採用した。別ウィンドウ対応・一覧の性能・IME・アクセシビリティ・各OSでの配布を評価して最終決定する。
